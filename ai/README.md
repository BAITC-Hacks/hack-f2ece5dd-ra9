# Локальная обработка совещаний

Цепочка: faster-whisper → транскрипт → pyannote Community-1 → поручения и краткие итоги → JSON/DOCX.
Обучение не требуется. Аудио и текст обрабатываются на компьютере, облачные API не используются.

## Установка на Windows

Из корня репозитория:

```powershell
.\setup.cmd
.\.venv\Scripts\python.exe -m pip install -r ai/requirements-diarization.txt
```

На [странице Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)
войдите в Hugging Face и примите условия доступа. Создайте read-токен с доступом к этой модели.
Затем скачайте веса (один раз, нужен интернет):

```powershell
.\.venv\Scripts\python.exe -m ai.download_diarization
```

Скрипт запросит токен скрытым вводом. Не вставляйте токен в код, чат или команду терминала.
Он используется только для скачивания весов и не записывается скриптом на диск.
Веса сохраняются в `models/diarization`, который исключён из Git.

Перед запуском сервера в том же окне PowerShell:

```powershell
$env:DIARIZATION_MODEL_PATH = (Resolve-Path .\models\diarization).Path
.\.venv\Scripts\python.exe -m backend
```

Откройте http://127.0.0.1:8765. Загрузите файл и нажмите кнопку распознавания либо запишите системный звук.
После завершения обработки откройте «Транскрипт и итоги». Сопоставьте голоса с именами, нажмите
«Сохранить имена», проверьте задачи и скачайте DOCX.

faster-whisper по умолчанию использует `base`, CPU/int8 и скачивает веса при первом распознавании.
Диаризация запускается на CPU по полной записи после остановки. Во время записи доступны
реплики с неизвестным говорящим; устойчивые метки появляются в итогах.

## CLI

В том же PowerShell с заданным `DIARIZATION_MODEL_PATH`:

```powershell
.\.venv\Scripts\python.exe -m ai.pipeline "C:\путь\совещание.mp3" meeting-result.json --docx meeting-result.docx
```

Только транскрипция или анализ существующего JSON:

```powershell
.\.venv\Scripts\python.exe -m ai.transcriber "C:\путь\совещание.mp3" transcript.json
.\.venv\Scripts\python.exe -m ai.analyzer transcript.json result.json
```

Вход анализатора: `{"segments": [{"speaker": "Алия", "start": 1.0, "end": 5.0, "text": "..."}]}`.
Поддерживается также поле `speaker_id` от backend. Время — секунды от начала встречи.
JSON с UTF-8 BOM принимается.

Итог pipeline / API содержит `transcript.segments`, `summary`, `tasks`, `speaker_names`,
`diarization_status`, `warnings`. У задачи есть `title`, `responsible`, `responsible_id`,
`deadline`, `evidence` (цитата и время), `requires_review`.

## Ограничения

- Диаризация различает голоса, но не устанавливает ФИО. Имена задаёт оператор.
  Исполнитель берётся из текста поручения; говорящий становится исполнителем только при явном
  личном обязательстве («я подготовлю»). Неоднозначные имена не связываются автоматически.
- Сегменты, где один голос занимает менее 80% интервала, остаются `speaker-unknown`.
  Разделения текста по отдельным словам пока нет.
- Без модели или при ошибке диаризации транскрипт сохраняется с предупреждением.
  Такой результат не закрывает обязательное требование ТЗ о разделении голосов.
- Анализатор использует правила русского и казахского языка. Саммари — отбор значимых фраз
  и найденных задач, а не генеративная языковая модель. Возможны пропуски, повторы и ошибки;
  косвенные поручения, исправления сроков и сложный контекст требуют проверки.
- Относительные сроки («завтра») сохраняются как сказано, без выдуманной календарной даты.
- Качество русского, казахского и смешанного аудио и настоящая диаризация требуют отдельного
  прогона на ноутбуке. Тесты с подменённой моделью этого не подтверждают.
- Загрузка ограничена 200 МБ. Форматы: WAV, MP3, M4A, OGG, OPUS, FLAC, WebM, MP4.
  Записи длиннее двух часов отклоняются после декодирования; для демо используйте короткую запись.

## Проверка и автономная работа

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

Тесты проверяют правила, таймкоды, привязку имён, API и содержимое DOCX. ML-вывод в них подменён.
Перед демо запишите короткое синтетическое совещание с двумя голосами: русский,
казахский и смешанный фрагменты, несколько явных поручений и одно личное обязательство.
Проверьте вручную текст, говорящих, исполнителей, сроки и откройте DOCX.

После предварительного скачивания обеих моделей запустите сервер без интернета и повторите
обработку. Диаризация использует локальный путь и отключает телеметрию pyannote.
Модель Whisper также должна быть заранее загружена в `models/`.
Записи и результаты находятся в `sessions/` и не должны попадать в Git.
Для демонстрации используйте вымышленную запись либо обезличенные данные.
