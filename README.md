# AI Протоколист — команда rA9

Проект для хакатона HackAlem AI по кейсу «Система автопротоколирования совещаний с фиксацией поручений».

Приложение должно записывать звук совещания, распознавать реплики участников и формировать протокол с поручениями, ответственными и сроками. Цель — сократить ручную работу секретаря и уменьшить риск потери договорённостей.

## Текущий статус

Реализована первая версия локального интерфейса без внешних зависимостей: HTML, CSS и JavaScript. В репозитории также находятся тестовые записи и эталонные документы.

В интерфейсе доступны:

- Ввод названия встречи и выбор сценария Teams / Zoom; это настройка интерфейса, а не подключение к платформе.
- Воспроизведение вымышленного примера: шесть реплик, три говорящих и три заранее заданных поручения.
- Редактирование имён участников с обновлением транскрипта и ответственных; отметка проверки поручений.
- Экспорт демонстрационного транскрипта в TXT и структурированных результатов в JSON. Файлы явно помечены как демонстрационные.
- Выбор локального аудиофайла, отображение имени, размера и длительности, встроенное прослушивание. Поддерживаемые расширения: MP3, WAV, M4A, OGG, OPUS, FLAC, WebM; предел размера — 200 МБ. Возможность прослушивания зависит от кодеков браузера.
- Адаптивная компоновка для широкого и узкого экрана.

При выборе настоящего файла вымышленные результаты очищаются. Файл остаётся в браузере и не отправляется на сервер. Кнопка распознавания недоступна до подключения модели.

Захват звука, распознавание, диаризация, извлечение поручений с помощью ИИ и экспорт DOCX ещё не реализованы. При перезагрузке страницы результаты интерфейса сбрасываются.

Следующие разделы описывают план полного MVP. Модели и параметры API будут выбраны после получения доступа к GPT Sandbox и проверки его каталога.

## Планируемый сценарий

1. Оператор вручную входит во встречу отдельным аккаунтом «AI Протоколист» на компьютере с Windows. Микрофон этого аккаунта выключен, участники уведомлены о записи и обработке речи.
2. В локальном интерфейсе оператор выбирает устройство воспроизведения и начинает запись системного звука.
3. Приложение обрабатывает поступающий звук фрагментами и постепенно показывает транскрипт с таймкодами и обозначениями говорящих.
4. Из транскрипта извлекаются поручения и обновляются предварительные итоги.
5. После завершения записи приложение обрабатывает оставшееся аудио и формирует два итоговых файла.

Основная платформа демонстрации — Microsoft Teams. Совместимость с Zoom планируется проверить отдельно. Захват звука должен работать через устройство вывода Windows; автоматическое подключение бота по ссылке встречи в MVP не входит.

## Планируемые функции MVP

- Запуск и остановка записи, выбор источника и индикатор поступления звука.
- Распознавание русского, казахского и смешанной русско-казахской речи.
- Разделение говорящих: «Спикер 1», «Спикер 2» и далее, с возможностью вручную сопоставить обозначения с именами.
- Транскрипт с таймкодами, пополняемый во время встречи.
- Извлечение поручений: содержание задачи, ответственный, срок и подтверждающая цитата из транскрипта.
- Отметка «не указан», если исполнитель или срок не названы; неоднозначные поручения требуют проверки оператором.
- Предварительное саммари во время встречи и итоговое саммари после её завершения.
- Сохранение промежуточных результатов в локальную папку совещания.
- Экспорт исходного результата распознавания в `transcript.txt` и итогового протокола в `summary.docx`.

`summary.docx` должен содержать краткие итоги и таблицу поручений. Транскрипт сохраняется без редакторского пересказа, но может содержать ошибки распознавания.

## Архитектура и технологии

Планируемая цепочка обработки:

```text
Звук Teams / Zoom → захват Windows → распознавание и диаризация
→ транскрипт → извлечение поручений и саммари → TXT / DOCX
```

- Python — обработка аудио, взаимодействие с моделями и экспорт документов.
- Локальный веб-интерфейс — управление записью и просмотр результатов.
- WASAPI loopback — предполагаемый механизм захвата звука устройства воспроизведения Windows.
- GPT Sandbox — предполагаемый провайдер моделей. Наличие аудиомоделей, диаризации, нужных языков и подходящих лимитов ещё предстоит проверить.
- Локальное распознавание — запасной вариант при отсутствии подходящего аудио API; модель и производительность не определены.
- Локальные JSON-файлы — хранение структурированных результатов. База данных и регистрация пользователей для MVP не нужны.

Адрес сервиса и названия моделей будут задаваться в конфигурации. Секретные API-ключи не должны попадать в Git, README, демонстрационные материалы или журналы приложения.

## Ограничения и открытые вопросы

- Live-обработка означает последовательную обработку поступающего звука с задержкой. Фактическая задержка и способность работать без накопления очереди пока не измерены.
- Качество казахской и смешанной речи, разделение голосов и устойчивость обозначений спикеров между фрагментами требуют проверки на тестовых записях.
- Диаризация отделяет голоса друг от друга, но сама по себе не устанавливает имена и должности людей.
- Системный захват может включать посторонние звуки выбранного устройства. Для демо следует отключить уведомления и другие источники воспроизведения.
- Звук локального микрофона не гарантируется системным захватом. Для основного сценария используется отдельный аккаунт слушателя, получающий речь остальных участников через встречу.
- В исходном документе кейса предусмотрен закрытый контур. Использование внешнего API рассматривается на основании сообщённого командой разрешения организаторов; применимость разрешения к GPT Sandbox нужно уточнить до отправки туда записей.

В MVP не входят определение руководителя по тону, автоматический вход во встречи, напоминания о сроках, рассылка поручений, интеграция с СЭД, история с поиском и промышленное развёртывание.

## Тестовые материалы

В папке `Assets/` находятся:

- `Совещание №1.mp3` и `Совещание №2.mp3` — тестовые аудиозаписи.
- `Протокол_совещания№1.docx` и `Протокол_совещания№2.docx` — предоставленные командой документы для сверки результатов.

Эталонные документы используются для оценки качества, а не для подстановки заранее подготовленных ответов. Реальные записи должны быть анонимизированы перед публичной демонстрацией.

## Запуск

Для интерфейса не нужны API-ключи, npm и установка библиотек.

Вариант 1: откройте `ui/index.html` в современном браузере.

Вариант 2: при установленном Python 3 запустите из корня репозитория:

```powershell
.\start-ui.cmd
```

Откройте `http://127.0.0.1:8765`. Сервер доступен только на этом компьютере и обслуживает папку `ui`, а не весь репозиторий. Для остановки нажмите Ctrl+C в терминале. Если порт занят, завершите предыдущий экземпляр сервера либо используйте другой порт:

```powershell
python -m http.server 8766 --bind 127.0.0.1 --directory ui
```

Для проверки интерфейса нажмите «Запустить пример», отредактируйте имя участника и скачайте TXT / JSON. Для проверки входного аудио нажмите «Загрузить аудиофайл» и выберите запись из `Assets/`. Проверьте длительность и прослушивание. Наличие выбранного файла пока не запускает ИИ-обработку.

После подключения backend этот раздел будет дополнен настройкой провайдера моделей, ключей и реальной записи звука.
