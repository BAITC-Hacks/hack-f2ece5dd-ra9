# Backend записи совещаний

Backend на FastAPI записывает системный звук Windows через WASAPI loopback. Распознавание речи и ИИ-анализ не подключены. Запуск: `python -m backend`, по умолчанию `http://127.0.0.1:8765`. Используйте Python из `.venv`; зависимости устанавливает `setup.cmd`.

## Teams

`POST /api/teams/open` открывает проверенную HTTPS-ссылку встречи в Edge InPrivate, либо Chrome Incognito, если Edge не найден. Имя гостя, выбор входа в браузере, выключение микрофона/камеры, проверка email и ожидание допуска выполняются оператором. Приложение не читает список участников, не определяет вход или выход из встречи и не обходит ограничения организатора. Ответ `browser_opened` означает только запуск окна, а не присоединение. Запись запускается и останавливается отдельно.

Гость должен получать звук через то же устройство вывода, которое выбрано в приложении. Микрофон компьютера не записывается. Для захвата собственного выступления организатора используйте отдельный компьютер гостя или воспроизводите тестовый файл через встречу с другого устройства. Записываются все звуки выбранного устройства; уведомления и другие приложения могут попасть в WAV.

## API

OpenAPI доступен по `/docs`. Перед POST-запросами получите `csrf_token` из `/api/status` и передавайте его в заголовке `X-Recorder-Token`. Для браузерных запросов требуется тот же origin. Сервер слушает только loopback; ключи облачных моделей не используются.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/status` | Текущая сессия, уровень звука, состояние backend и токен для POST |
| `GET /api/devices` | Loopback-устройства, их ID, частота, каналы, устройство по умолчанию |
| `POST /api/teams/open` | `{ "url": "https://teams.microsoft.com/meet/..." }` — открыть гостевое окно |
| `POST /api/recordings/start` | `{ "device_id": 10, "title": "Планёрка", "platform": "Teams", "acknowledged": true }` |
| `POST /api/recordings/stop` | `{}` — остановить поток и завершить WAV |
| `GET /api/sessions` | До 100 последних сессий |
| `GET /api/sessions/{id}` | Метаданные и список готовых фрагментов |
| `GET /api/sessions/{id}/files/recording.wav` | Полная запись после остановки |
| `GET /api/sessions/{id}/files/chunk-00000.wav` | Завершённый фрагмент, доступный и во время записи |

Одновременно разрешена одна запись на процесс. Повторный запуск во время записи возвращает HTTP 409. Остановка повторным запросом безопасна. Файл полной записи недоступен по API, пока запись не завершена; готовые фрагменты доступны сразу. Не запускайте несколько экземпляров backend с общей папкой `sessions`.

## Контракт для разработчика распознавания

После старта backend создаёт папку `sessions/<id>/`:

```text
session.json
recording.wav
chunk-00000.wav
chunk-00001.wav
...
```

WAV содержит PCM signed 16-bit little-endian. Частота и число каналов берутся из устройства; на проверенном компьютере это 48000 Гц и 2 канала. Не предполагайте, что вход всегда mono/16 kHz: преобразование формата выполняйте перед вызовом своей модели.

Пример части `session.json`:

```json
{
  "schema_version": 1,
  "id": "32-символьный-идентификатор",
  "source": "wasapi_loopback",
  "status": "recording",
  "sample_rate": 48000,
  "channels": 2,
  "sample_width": 2,
  "audio_file": "recording.wav",
  "duration_seconds": 10.2,
  "chunks": [
    {"index": 0, "file": "chunk-00000.wav", "start": 0, "duration": 5.0},
    {"index": 1, "file": "chunk-00001.wav", "start": 5, "duration": 5.0}
  ]
}
```

Опрашивайте метаданные и обрабатывайте новые элементы `chunks` по паре `(id, index)`. Список обновляется после закрытия WAV-фрагмента. Последний фрагмент короче пяти секунд. `.part` и `.tmp` не являются готовыми файлами. Метаданные публикуются атомарно; порядок определяется `index`, а `start` — смещение в аудио сессии. В пределах одной непрерывной записи PCM фрагментов в сумме точно равен PCM `recording.wav`, без перекрытия или удаления пауз.

Граница пяти секунд может разрезать слово. Разработчику ASR следует использовать соседние фрагменты или контекст, а также сохранять соответствие таймкодов. Этот backend не решает диаризацию, устойчивость ID спикеров или дедупликацию текста.

Статусы: `starting`, `recording`, `stopping`, `completed`, `error`, `interrupted`. Обрабатывайте `error` и `warning`; завершённые фрагменты могут сохраниться и при ошибке. После аварийного завершения процесса прошлые активные сессии помечаются как `interrupted`. Закрытие вкладки не останавливает backend-запись. Перед выходом нажмите «Остановить и сохранить».

Ограничения: максимум 1 ГБ PCM или 2 часа на сессию, остановка при нехватке диска, проверка переполнения очереди. Полная запись и фрагменты хранятся одновременно, поэтому место расходуется примерно вдвое. Доступного пространства должно быть не менее 512 МБ перед стартом; во время записи выполняются повторные проверки.

## Проверки

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются целостность WAV и точная сборка фрагментов, частичный последний фрагмент, пустая запись, восстановление статуса после прерывания, проверка Teams URL, защита POST-запросов, повторный старт, остановка и ограничения скачивания. Эти тесты не требуют аудиооборудования. Проверку звука и Teams выполняйте отдельно на Windows.

23 сентября 2026 года проведена проверка в тестовой встрече Teams с участием оператора: запись 114.73 секунды, 48000 Гц, stereo PCM16, 23 фрагмента. Подтверждены ненулевой сигнал, завершение без ошибки и точное совпадение объединённых фрагментов с полной записью. Полностью автоматический вход гостя и Zoom не проверялись.
